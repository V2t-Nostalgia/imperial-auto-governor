# Stellaris 4.4.6 轨道轰炸命令

2026-09-12 的非房主合作端样本确认，轨道轰炸不是一条同时包含姿态和目标的单独命令，
而是两步组合：先设置舰队的地面支援姿态，再让舰队移动到目标殖民地行星对象。舰队抵达
轨道后，由游戏依据战争状态和姿态自动开始轰炸。

## 轰炸姿态命令族

`d62d01000300` 是舰队地面支援姿态命令族。三种基础姿态均已取得非房主客户端请求和
房主权威回包：

| 姿态字符串 | 记录长度 | 客户端 serial | 房主 serial | 配对结果 |
|---|---:|---:|---:|---|
| `raiding` | 99 | 24 | 45 | 清零 serial 后逐字节相同 |
| `selective` | 101 | 25 | 46 | 清零 serial 后逐字节相同 |
| `indiscriminate` | 106 | 26 | 47 | 清零 serial 后逐字节相同 |

三个请求使用同一 actor 2、origin 0 和来源舰队 4778，客户端与房主 serial 均连续。
姿态命令的业务字段为：

| 偏移 | 标签或值 | 含义 |
|---:|---|---|
| `70..75` | `502c01001400` | 来源舰队标签 |
| `76..79` | u32 | 来源舰队对象 |
| `80..85` | `d22d01000f00` | 姿态字符串标签 |
| `86..87` | u16 | ASCII 字符串长度 |
| `88..(88+N-1)` | ASCII | 姿态字符串 |
| 字符串后 4 字节 | `04000400` | 稳定尾部 |

三条记录满足 `record_length = 92 + N`，其中 `N` 是姿态字符串字节数。清零记录长度、
serial、字符串长度并移除字符串后，三个客户端请求形成完全相同的 92 字节结构骨架。
这证明姿态不是隐藏枚举，而是 `d22d` 标签承载的长度前缀 ASCII 脚本 ID。

## 进入目标行星轨道

第二条记录是现有的 116 字节 `d32c01000300` 移动命令：

| 偏移 | 标签或值 | 含义 |
|---:|---|---|
| `70..75` | `502c01001400` | 来源舰队标签 |
| `76..79` | u32 | 来源舰队对象 |
| `80..86` | `634001000e0000` | 已验证固定标志 0 |
| `87..93` | `de3501000e0000` | 已验证固定标志 0 |
| `94..99` | `8b3d01000300` | 目标对象容器 |
| `100..105` | `132a01001400` | 行星对象目标标签 |
| `106..109` | u32 | 目标殖民地行星对象 |
| `110..115` | `040004000400` | 稳定尾部 |

样本中的来源舰队为 4778，目标行星为 70。同步存档确认行星 70 是罗德尔星系
（system 6）的敌方殖民地。该记录由现有 `build_fleet_move_record()` 使用相同结构化字段
重建后，与抓包逐字节相同；无需新增第二套移动序列化器。

## 自动化边界

实现轨道轰炸时应把它建模为受同一行动锁保护的两步事务：

1. 从最新同步存档选择玩家已授权、可用且能抵达目标的军用舰队；
2. 只允许选择已确认处于战争中的敌方殖民地行星对象；
3. 发送 `d62d` 并等待房主权威确认；
4. 使用现有 `d32c` 的 `132a` 形式移动到该殖民地，并再次等待房主确认；
5. 最终是否抵达及是否开始轰炸仍由后续同步存档确认。

`raiding`、`selective` 和 `indiscriminate` 均已通过完整请求/回包配对，可以作为同一
参数化命令族的白名单值。飞升、特殊政体或 Mod 增加的其他姿态仍需由 Content Pack
声明，并在对应版本取得证据后才能启用。
