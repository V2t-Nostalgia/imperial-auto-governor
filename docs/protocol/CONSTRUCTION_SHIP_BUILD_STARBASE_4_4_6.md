# Stellaris 4.4.6 工程船建造恒星基地

本文汇总三次非房主合作端下达工程船建造恒星基地命令的捕获。三次捕获均只观察
网络，没有运行数据包改写器。

## 样本

| 日期 | 界面目标 | 来源舰队 | `e92d` 目标 | 客户端请求 | 房主权威广播 |
|---|---|---:|---:|---|---|
| 2026-09-04 | Gehar | 2 | 248 | 捕获缺失；serial 49 为推定 | 完整，serial 19114 |
| 2026-09-05 | 许尔巴克之喉 | 2 | 188 | 完整，serial 113 | 捕获缺失；完整传输 ACK 存在 |
| 2026-09-05 | 与上一样本相同的目标 | 2 | 188 | 完整，serial 117 | 完整，serial 55251 |

前两个样本互相补足：第一份提供房主权威记录，第二份提供真实客户端请求。第二份请求与
第一份推定请求在清零 command serial 和 `e92d` 目标对象后逐字节相同。第三份样本零
丢包地捕获了同一次动作的完整请求与权威广播，关闭了配对证据缺口。

## 命令结构

| 项目 | 值 |
|---|---|
| 命令族 | `e02c01000300` |
| 记录长度 | 114 字节 |
| 应用前缀 | `000000` |
| 应用总长度 | 117 字节 |

| 标签 | 作用 | 样本值 |
|---|---|---:|
| `400201000c00` | actor | 2 |
| `130401000e00` | origin | 0 |
| `502c01001400` | 来源工程船舰队 | 2 |
| `e92d01001400` | 建造目标对象 | 248、188 |
| `634001000e00` | 已观察标志 | 0 |
| `de3501000e00` | 已观察标志 | 0 |

来源字段复用了其他舰队命令中已确认的 `502c`。在保持来源舰队不变时，更换目标星系只
改变 `e92d`，证明它是建造目标对象引用。现有证据尚不能区分该对象在存档中属于星系还是
主恒星条目。

完整配对中，房主广播与客户端请求清零四字节 command serial 后逐字节相同。客户端
sender offset 与房主 ACK offset 的差为 117，恰好等于 3 字节命令前缀和 114 字节记录。
房主还重传了一次相同权威记录，说明观察器和确认器必须对可靠流重传去重。

## 参数化与执行约束

构造器不需要为每个目标保存整包模板，但必须：

1. 从当前同步存档读取 actor、可调用工程船舰队以及目标对象引用；
2. 只向已勘探、未占领且游戏规则允许建设前哨站的目标生成候选；
3. 在当前可靠流边界生成 serial，并按 117 字节应用长度维护 framing；
4. 不得复用其他存档、房间或同步 epoch 中的来源舰队与目标对象 ID；
5. 以房主权威广播或后续同步存档确认命令成立，传输 ACK 只能证明收包；
6. 在没有同一时点存档对象映射时，不允许模型直接提交裸 `e92d` 数值。

当前协议结构已由三次实机动作确认，其中第三次提供了同动作、零丢包的双向完整配对。版本
兼容性验收仍应重新执行真实命令检查，因为游戏更新可能改变命令族、标签或记录长度。
