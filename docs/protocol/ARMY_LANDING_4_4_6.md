# Stellaris 4.4.6 陆军登陆命令

2026-09-12 的非房主合作端样本确认，运输舰队登陆敌方殖民地使用独立的
`6f3301000300` 命令族。它不复用军用舰队跨星系移动的 `d32c` 目标结构。

## 已确认样本

| 项目 | 值 |
|---|---|
| 命令族 | `6f3301000300` |
| 记录长度 | 108 字节 |
| 客户端 actor / origin / serial | 2 / 0 / 27 |
| 房主 actor / origin / serial | 2 / 0 / 48 |
| 来源运输舰队 | 33554946，5 艘运输船 |
| 目标 | 罗德尔 system 6、planet 70、colony 4 |

会话代理在客户端请求后约 224 ms 观察到同 actor、同 origin、同记录长度的房主广播，
说明房主接受并转发了该命令。本次 NIC 层 PktMon 文件完整保留了客户端记录，但未保留
房主广播的完整正文，因此证据等级为“请求完整 + 房主结构配对”，尚不能声称清零 serial
后两条记录逐字节相同。

## 请求字段

| 偏移 | 标签或值 | 含义 |
|---:|---|---|
| `70..75` | `502c01001400` | 来源舰队标签 |
| `76..79` | u32 | 来源运输舰队对象，本次为 33554946 |
| `80..85` | `1e3901001400` | 目标殖民地标签 |
| `86..89` | u32 | 目标 colony 对象，本次为 4 |
| `90..96` | `634001000e0000` | 已观察固定标志 0 |
| `97..103` | `de3501000e0000` | 已观察固定标志 0 |
| `104..107` | `04000400` | 稳定尾部 |

`1e39` 的语义由存档交叉验证，而不是按数值猜测：罗德尔的 `galactic_object=6`
包含 `colonies={ 4 }`，目标 `planet=70` 同时保存 `colony=4`。因此该字段不是星系 ID
或行星 ID，而是顶层 `colony` 对象 ID。

## 自动化边界

执行器接入时应由固定程序完成以下工作：

1. 从最新同步存档选择玩家明确授权、仍存在且不处于 MIA 的 `shipclass_transport` 舰队；
2. 将玩家或模型选择的目标行星解析为其当前 `colony` 对象，不允许模型直接填写对象 ID；
3. 校验目标仍为战争敌方控制的可登陆殖民地，并验证运输舰队存在可作战陆军；
4. 在同一行动锁内重新核验源舰队、目标 colony 与外交状态后发送 `6f33`；
5. 以房主权威确认和后续同步存档确认登陆结果，不从客户端动画推断占领成功。

本样本只验证了同星球的一次登陆请求。目标已无防御陆军、登陆失败、撤退以及跨星系
自动寻路等分支仍需由规则层保守处理；在取得差分证据前不得为固定标志赋予业务语义。
