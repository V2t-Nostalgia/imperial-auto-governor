# Stellaris 4.4.6 殖民请求记录

本文件记录 2026-09-05 在已授权联机测试中被动捕获的“选择城市星球规划并确认殖民”
请求。本文只固化可复核的协议结构，不代表该动作已经开放给 Agent。

## 已确认结构

| 项目 | 值 |
|---|---|
| 命令族 | `3d3701000300` |
| 应用前缀 | `000001` |
| 记录长度 | 286 字节 |
| 应用总长度 | 289 字节 |
| 客户端请求与房主回包 | 除 command serial 外逐字节相同 |

长度声明为 `0x011d = 285`，实际记录长度为 286。扩展长度规则见
`APPLICATION_COMMAND_FRAMING_4_4_6.md`。

## 已由界面与存档交叉确认的字段

| 标签 | 样本值 | 含义与证据 |
|---|---:|---|
| `822c01001400` | 0 | 当前命令上下文；沿用中性名称 `context_822c` |
| `4c2b01001400` | 385875969 | 殖民物种 ID；存档 `species_db` 中对应人类 |
| `cd2a01000f00` | `col_city` | 玩家在确认前选择的“城市星球”殖民地规划 |
| `652c01001400` | 2 | 殖民船设计 ID；存档 `ship_design=2` 的舰船尺寸为 `colonizer` |
| `143501001400` | `0xffffffff` | 设计升级 ID；与现有舰船构造协议一致，当前未指定 |
| `c84401000c00` | 0 | 设计 growth stage；与现有舰船构造协议一致 |
| `962d01001400` | 276 | 目标行星 ID；存档中为半人马座阿尔法 III |
| `c33d01001400` | 3 | 出发／建造行星 ID；存档中为地球 |

命令还包含 `d83d01001400 = 0xffffffff`。当前样本不足以命名该可选对象。后续现成
殖民船样本确认该路径改用独立的 `e62c` 命令族，而且记录中完全没有 `d83d`；因此不能
再把 `d83d` 当作现成殖民船 ID。实现不得为该字段编造语义，在取得真正使它变化的差分
样本前只能保留已验证的 `0xffffffff`。

## 名称对象

当前默认名称不是一段直接显示文本，而是嵌套的本地化对象：

```text
NEW_COLONY_NAME_1
  NAME = NAME_Alpha_Centauri
```

构造器不能从显示语言反向拼接该对象。应从目标星系的存档名称结构生成，或保留一个经
验证的默认命名策略；自定义文字名称需要另行差分验证。

## 城市／矿产规划差分

第二次捕获保持目标行星、殖民物种、殖民来源和默认名称均不变，只把初始殖民地规划从
`col_city` 改为 `col_mining`：

| 规划键 | 字符串长度 | 记录长度 | 应用总长度 |
|---|---:|---:|---:|
| `col_city` | 8 | 286 | 289 |
| `col_mining` | 10 | 288 | 291 |

将两条客户端请求的 command serial 和记录长度低字节归零，再移除 `cd2a01000f00`
之后的长度前缀规划字符串，两条规范化记录均为 278 字节且逐字节相同。因此，在这组
受控样本中，唯一的业务差异就是殖民地规划键；多出的 2 个字符串字节也准确反映在记录
长度、应用总长度和可靠流 sender offset 增量中。

这证明该字段可以作为参数编码，不需要为每一种原版规划分别保存整包模板。构造器应：

- 在 `cd2a01000f00` 后写入 16 位小端字符串长度和 ASCII 规划键；
- 根据完整记录重新计算记录长度低字节及三字节应用前缀中的长度高字节；
- 只接受当前游戏规则或 Content Pack 明确列入白名单的规划键，不能仅凭 `col_*` 前缀
  猜测其合法性；
- 在发包前仍按目标行星、物种、玩家权限和资源状态做确定性校验。

## 现成殖民船发起殖民

第三次样本由玩家选中已经存在的殖民船 `UNS澳大利亚`，在相同目标行星上选择
“城市星球”后确认殖民。该动作没有复用上述 `3d37` 请求，而是使用独立命令族：

| 项目 | 值 |
|---|---|
| 命令族 | `e62c01000300` |
| 应用前缀 | `000000` |
| 记录长度 | 200 字节 |
| 应用总长度 | 203 字节 |
| 客户端 command serial | 32 |
| 房主 command serial | 10334 |
| 客户端请求与房主回包 | 除 serial 的两个有效字节外逐字节相同 |

可靠流 sender offset 从 582265 增至 582468，增量恰好为 203 字节。已确认记录字段为：

| 标签 | 样本值 | 含义与证据 |
|---|---:|---|
| `502c01001400` | 16777936 | 来源殖民船舰队的传输对象；该标签已由其他舰队命令族确认 |
| `132a01001400` | 276 | 目标行星 ID；与前两次样本的半人马座阿尔法 III 相同 |
| `634001000e00` | 0 | 与其他舰队命令共享的未命名布尔标志 |
| `de3501000e00` | 0 | 与其他舰队命令共享的未命名布尔标志 |

该记录仍携带默认殖民地名称对象，但不包含 `d83d`、物种 ID、殖民船设计 ID、出发行星
ID 或 `col_city` 规划键。这说明“订购殖民船并殖民”与“现成殖民船执行殖民”是两种
不同协议动作。当前单一样本还不能说明现成殖民船路径如何持久化界面所选规划；在接入
自动化前，应以殖民开始后的存档或另一条现成殖民船规划差分验证这一点。

## 不同目标行星差分

第四次样本再次从行星界面订购殖民船，保持人类物种、殖民船设计、地球出发地及
`col_city` 规划不变，但把目标改为布隆戴 IVa。同步存档确认该目标为 `planet=2838`，
位于 `Blondei` 星系，类型为 `pc_arctic`，大小为 14。

| 项目 | 半人马座阿尔法 III | 布隆戴 IVa |
|---|---:|---:|
| `962d` 目标行星 ID | 276 | 2838 |
| 嵌套 `NAME` 值 | `NAME_Alpha_Centauri`（19 字节） | `Blondei`（7 字节） |
| `c33d` 出发行星 ID | 3 | 3 |
| `d83d` | `0xffffffff` | `0xffffffff` |
| 记录长度 | 286 | 274 |
| 应用总长度 | 289 | 277 |

新样本的客户端 serial 为 85，房主 serial 为 38580；请求与房主权威回包仍然只有
serial 两个有效字节不同。客户端 sender offset 从 2079909 增至 2080186，增量恰好为
277 字节。

清零 command serial、记录长度声明和目标 ID，再移除动态 `NAME` 字符串后，两条城市
星球请求均规范化为 267 字节且逐字节相同。这确认不同目标只需参数化 `962d` 与目标
星系名称对象，没有观察到第二个随目标变化的隐藏字段。记录长度减少 12 字节也完全等于
两个名称值的长度差。

名称构造不能假定星系键总带 `NAME_` 前缀。本次名称对象为：

```text
NEW_COLONY_NAME_1
  NAME = Blondei
```

构造器应从存档复制或结构化序列化目标星系的名称对象，而不是从本地化后的显示文本反向
猜测。`d83d` 在目标、星系和宜居性均改变后仍为 `0xffffffff`，因此可以进一步排除它是
普通目标行星或目标星系字段，但目前仍不得为其编造用途。

## 自动化前置条件

未来将该命令开放给 Agent 前，固定程序至少必须从最新存档校验：

- 目标行星仍未殖民且当前玩家可殖民；
- 目标的宜居性、行星类型、阻塞项和殖民成本；
- 物种 ID 对目标行星有效；
- 殖民船设计属于当前玩家且仍为 `colonizer`；
- 出发行星属于当前玩家并允许发起殖民；
- 玩家选择的初始殖民地规划在当前规则与 Content Pack 中有效；
- 资源仍足够，且同一目标没有已发出的待确认殖民请求。

宜居性和合法目标必须来自存档及规则层，不应由模型根据行星名称猜测。

## 尚需验证

- `d83d` 的精确语义；
- 自定义殖民地名称的编码；
- 不同物种的配对差分；
- 现成殖民船路径如何记录初始殖民地规划；
- 发出请求后的存档确认字段与失败／取消状态。
