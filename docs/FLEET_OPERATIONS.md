# 舰队与扩张实验功能

`fleet_operations` 默认关闭。它把存档证据、匹配版本的原版规则、全局实验开关和逐船队授权组合成强制执行边界，而不是让模型从名称猜测对象 ID。

## 存档视图

`fleet_profiles.py` 读取玩家国家拥有的 fleet 对象，并报告：

- 对象 ID、可显示名称与舰船数量；
- 军事战斗力；
- 每艘船按自身最大值归一化后，船体、装甲和护盾剩余百分比的舰队平均数、中位数与样本舰数；不向模型展开单舰耐久列表；
- 当前星系、移动目标与路径证据；
- 当前与目标的星系内 X/Y 坐标，以及存档可确认的行星坐标目标；
- 交战、MIA、不可用或证据不确定状态；
- 当前是否属于玩家可直接控制的舰队；
- `d32c` 可使用的已验证目标对象与字段形式。
- 关联的 Fleet Manager 模板、各设计当前舰数、目标总数和已排队增援句柄；
- 玩家拥有的舰船设计 ID，供编制工具做确定性校验；
- 己方船坞的 `shipyard_build_queue`，供舰队升级和订购殖民船使用；
- 玩家 `intel.hostile` 中可与全局舰队对象按所有者、位置和军力唯一匹配的当前敌对目标；
- 科研船、工程船的船型和当前民用任务可用性；
- 已发现、完整勘探、无主且没有恒星基地的相邻建站目标。

`expansion_profiles.py` 另行读取物种偏好、殖民船设计、船坞来源、可殖民行星、恒星基地等级、建设队列、模块和建筑槽。宜居度与普通原版恒星基地规则来自玩家配置的匹配版本 `game_root`，无法解析时不生成相应候选。

恒星基地、采矿站等 `station=yes` 对象会保留在底层证据中，但不会显示为可授权舰队。

## 权限

1. 玩家先打开所需能力的独立总开关；舰队移动、维修／升级、民用船、殖民、恒星基地、舰船设计和编制增援互不代替。
2. 每支新发现舰队或民用船的移动、攻击、维修、升级、编制增援、自动化与工程船建站权限默认都是关闭。
3. 玩家在前端逐舰队授权；准备和执行阶段都会重新读取权限与最新存档。
4. MIA、正在交战、已消失、非玩家所有或目标映射不明确的舰队拒绝执行。
5. 恒星基地已有模块或建筑的替换还需要单独开启高影响替换开关。

模型只能看到当前被平台暴露的工具，不能通过自然语言绕过权限。

## 当前能力

- `inspect_fleet_state`：读取结构化舰队视图。
- `prepare_fleet_move`：验证来源舰队、目标和玩家授权。
- `prepare_fleet_coordinate_move`：在舰队当前星系内验证 X/Y 坐标、星系 origin、逐舰队授权和玩家设置的绝对值边界。
- `prepare_fleet_attack`：只接受玩家敌对情报与当前全局对象唯一匹配的目标，并要求逐舰队攻击权限。
- `prepare_fleet_repair`：只接受最新存档确认受损且当前可调用的军用舰队；游戏自行选择返港目的地。
- `prepare_fleet_upgrade`：只接受存在升级设计的可调用军用舰队，并要求从己方船坞列表选择精确的建设队列。
- `prepare_ship_automation`：只接受该科研船或工程船已实机验证的 `8f32` 选项集合。
- `prepare_construction_ship_starbase`：只接受工程船相邻、完整勘探、无主、无基地且没有可见敌军的星系。
- `inspect_expansion_state`：读取殖民和恒星基地候选及其存档/规则依据。
- `prepare_colonization`：准备 `3d37` 订购殖民船并殖民；初始规划目前只允许 `col_city` 或 `col_mining`。
- `prepare_starbase_operation`：准备普通恒星基地升级、模块或建筑操作，并区分空槽建设与已有组件替换。
- `execute_prepared_fleet_order`：通过已启动的会话代理发送上述刚准备的动作，执行前重建同一候选并记录机器事实。
- `inspect_ship_state`：读取玩家舰船设计和相关舰船状态，但不把完整组件候选库一次性塞入上下文。
- `inspect_ship_design_options`：先列出一份设计可用的区段与必需组件，再按选定区段展开合法槽位和组件。
- `prepare_ship_design`：以玩家现有设计为锚点创建新设计，支持多区段、空槽填充、普通组件、必需组件和自动升级；不覆盖原设计。
- `prepare_fleet_reinforcement`：把一个设计在指定舰队中的目标总数提高到 `target_count`，不是“额外造 target_count 艘”。
- `prepare_new_fleet`：创建一份空 Fleet Manager 模板，不预测返回 ID。
- `execute_prepared_ship_action`：严格串行确认模板增量与单条选中舰队增援请求；不把请求确认写成舰船完工。
- 固定存档续接器：新存档唯一确认模板 ID 后直接写入初始编制并请求增援，不消耗新的模型回合。

非房主 `6b33` 请求和房主权威回包已于 2026-09-05 完成零丢包配对验证。当前实现只从
玩家自己的 `intel.hostile` 观察出发，按敌方所有者、当前坐标与军力映射到唯一的全局
fleet 对象；无法唯一匹配、目标已经消失或来源舰队不再可用时失败关闭。

## 维修与升级

维修与升级共用一个独立总开关，并分别要求逐舰队 `allow_repair`、`allow_upgrade` 授权。
`8f32` 返港维修记录只携带来源舰队；目的地由游戏依据当前基地状态决定。候选层要求舰队
当前空闲、未交战、未失踪，并且船体、装甲或护盾聚合值能证明存在损伤。

`8f2f` 升级记录同时携带来源舰队和目标 `shipyard_build_queue`。后者由最新存档中己方
带船坞模块的恒星基地提取，不能使用星系 ID、恒星基地索引或 station 对象替代。候选层
还要求至少一艘舰船的 `ship_design_implementation.upgrade` 不是 `0xffffffff`。网络确认
只证明升级命令成立；修复完成度和设计变化仍以新存档为准。

## 民用船、殖民与恒星基地

- 科研船开放探索、勘探、特殊项目、异常现象、考古遗址、星界裂隙与投放重力陷阱中已经验证的选项；工程船开放采矿站、研究站、观测站与特殊项目。若存档显示科研船由内阁科学官带队，星界裂隙会从该舰的合法选项中移除。
- 工程船建站首版限制为当前星系的直接相邻星系。协议确认表示命令成立，不表示基地已经完工；后续存档仍是最终状态依据。
- 自动殖民使用最新存档中的创始物种、玩家殖民船设计和己方恒星基地的 `shipyard_build_queue`。最低宜居度由玩家设置；当前计算是原版物种偏好与无条件环境耐受的保守估计，不猜测事件或临时修正。
- 恒星基地只处理普通原版升级链以及已验证的 `shipyard`、`anchorage`、`crew_quarters`、`hydroponics_bay`。特殊、事件或 Mod 内容应由后续 Content Pack 提供映射。
- `e62c` 现成殖民船路径尚未证明初始规划字段如何持久化，因此只保留在协议兼容性套件，不向 Agent 开放。自动化取消 `6836` 同理不构造。

## 星系内坐标移动

`4f2c` 记录使用有符号 64 位小端整数保存 X/Y，比例为 `100000`。平台从最新存档读取舰队当前 `movement_manager.coordinate.origin`，不允许模型填写或跨星系替换该 origin。模型提交普通十进制坐标，确定性工具负责量化、范围检查和构包。

该能力有独立总开关，且仍受原有舰队移动总开关和逐舰队 `allow_move` 约束。默认坐标绝对值上限为 1000，玩家可在前端修改。成对抓包 fixture 已通过，新的自主发送链仍需下一轮多人实机闭环，因此目前标记为实验功能。

## 定量增援

当前协议证据显示，Fleet Manager 的 `+1` 不是一条绝对数量命令，而是每点击一次发送一条
`5f3b`。因此把目标从 1 提高到 4 必须发送三条独立命令，并分别等待房主确认。选中舰队的
“补充舰队”在干净抓包中只产生一条 `123b`；工具在全部目标增量确认后发送这条请求。
`f23b` 未出现在该动作中，现只作为未解析的全帝国增援证据保留，不会被自动追加。

第一版安全边界：

- 只允许玩家逐舰队启用 `allow_reinforce` 的军用舰队；
- Fleet Manager 模板、设计 ID、当前数量和目标数量都必须来自最新存档；
- 单次目标增量受玩家设置的 1–20 上限约束；
- 存档已有增援队列条目时拒绝重复提交；
- 不允许降低目标、删除舰船、猜测新模板 ID 或宣称舰船已经完工。

## 从零创建舰队

该能力有独立总开关和 1–20 的初始舰数上限，默认关闭。一次完整流程跨越两份存档：

1. 记录玩家当前拥有的模板 ID 集合并发送 `7e3b`；
2. 房主确认后写入战役级待办，但不猜测新 ID；
3. 等新存档中恰好多出一份玩家模板，上传事件立即唤醒固定续接器；
4. 固定续接器按目标数量逐条发送 `5f3b`，再发送单条 `123b`；
5. 再等新存档确认目标编制、队列和可能出现的实体舰队 ID。

若步骤 3 同时出现两份以上新模板，平台无法证明哪一份属于本次动作，因而停止。配置步骤
部分成功时也会等新存档重新计算剩余差额，不会盲目重放。同一份存档对同一工作流最多
尝试一次；续接动作发出后，该存档不再触发一次无意义的模型巡检。新实体舰队不会自动
写入逐舰队权限表，所以移动、攻击和后续增援仍然默认关闭。
