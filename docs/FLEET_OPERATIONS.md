# 舰队与扩张实验功能

`fleet_operations` 默认关闭。它把存档证据、匹配版本的原版规则、全局实验开关和逐船队授权组合成强制执行边界，而不是让模型从名称猜测对象 ID。

## 存档视图

`fleet_profiles.py` 读取玩家国家拥有的 fleet 对象，并报告：

- 对象 ID、可显示名称与舰船数量；
- 军事战斗力；
- 每艘船按自身最大值归一化后，船体、装甲和护盾剩余百分比的舰队平均数、中位数与样本舰数；不向模型展开单舰耐久列表；
- 当前星系、移动目标与路径证据；
- 当前与目标的星系内 X/Y 坐标，以及存档可确认的行星坐标目标；
- 交战、MIA、不可用或证据不确定状态；
- 当前是否属于玩家可直接控制的舰队；
- `d32c` 可使用的已验证目标对象与字段形式。
- 关联的 Fleet Manager 模板、各设计当前舰数、目标总数和已排队增援句柄；
- 玩家国家关联的舰船设计 ID，及其是否为当前可见设计；自动设计关闭后遗留的隐藏自动生成模板不会提供给模型作为设计锚点；
- 己方船坞的 `shipyard_build_queue`，供舰队升级和订购殖民船使用；
- 玩家 `intel.hostile` 中可与全局舰队对象按所有者、位置和军力唯一匹配的当前敌对舰队；
- 战略地图已知且属于当前交战国的恒星基地，以及按边境通行和敌对超空间抑制器计算的逐舰队可达性；
- 科研船、工程船的船型和当前民用任务可用性；
- 已发现、完整勘探、无主且没有恒星基地的相邻建站目标。

`expansion_profiles.py` 另行读取物种偏好、殖民船设计、船坞来源、可殖民行星、恒星基地等级、建设队列、模块和建筑槽。`invasion_profiles.py` 将交战国殖民行星、其 colony 对象、军用／运输舰队路径、陆军全局队列和招募空间站组合成入侵候选。宜居度与普通原版恒星基地、陆军规则来自玩家配置的匹配版本 `game_root`，无法解析时不生成相应候选。

恒星基地、采矿站等 `station=yes` 对象会保留在底层证据中，但不会显示为可授权舰队。

## 权限

1. 玩家先打开所需能力的独立总开关；舰队移动、维修／升级、民用船、殖民、恒星基地、入侵与陆军、舰船设计和编制增援互不代替。
2. 每支新发现舰队或民用船的移动、攻击、轰炸、登陆、维修、升级、编制增援、自动化与工程船建站权限默认都是关闭。
3. 玩家在前端逐舰队授权；准备和执行阶段都会重新读取权限与最新存档。
4. MIA、正在交战、已消失、非玩家所有或目标映射不明确的舰队拒绝执行。
5. 恒星基地已有模块或建筑的替换还需要单独开启高影响替换开关。

军用舰队的“可用”按动作能力分别计算。`move_system` 与 `move_wind_up` 表示舰队已有航行命令，游戏仍允许新移动或攻击命令替换旧命令，因此不会再把它们从可调舰队中整体剔除；维修和升级仍要求舰队没有当前命令并处于空闲、轨道或编队状态。前端和 Agent 工具会分别显示移动、攻击、增援与维护的即时可调用状态。

模型只能看到当前被平台暴露的工具，不能通过自然语言绕过权限。

## 当前能力

- `inspect_fleet_state`：读取结构化舰队视图。
- `prepare_fleet_move`：验证来源舰队、目标和玩家授权。
- `prepare_fleet_coordinate_move`：在舰队当前星系内验证 X/Y 坐标、星系 origin、逐舰队授权和玩家设置的绝对值边界。
- `prepare_fleet_attack`：只接受当前传感器确认的敌对舰队或战略地图已知的交战国恒星基地，并要求逐舰队攻击权限、当前存档可达路径，以及目标星系总体敌军的空间军力安全门槛。
- `inspect_campaign_deployment`：汇总战线投入军力、目标与走廊拥堵、无人覆盖的占领区／前沿驻防点，并按相对军力建议突破、战列线、掩护或守备角色。
- `inspect_campaign_routes`：对同一战争目标执行有界多目标 Pareto 路径搜索，显示完整路径、关闭边境、恒星基地／行星抑制器、已知风险、当前走廊占用与探索排序。
- `prepare_campaign_route`：保存模型选择的路线与地面策略，只准备当前可达的第一步；后续由固定存档续接器逐月复验和推进。
- `prepare_fleet_repair`：只接受最新存档确认受损且当前可调用的军用舰队；游戏自行选择返港目的地。
- `prepare_fleet_upgrade`：只接受存在升级设计的可调用军用舰队，并要求从己方船坞列表选择精确的建设队列。
- `prepare_ship_automation`：只接受该科研船或工程船已实机验证的 `8f32` 选项集合。
- `prepare_construction_ship_starbase`：只接受工程船相邻、完整勘探、无主、无基地且没有可见敌军的星系。
- `inspect_expansion_state`：读取殖民和恒星基地候选及其存档/规则依据。
- `prepare_colonization`：准备 `3d37` 订购殖民船并殖民；初始规划目前只允许 `col_city` 或 `col_mining`。
- `prepare_starbase_operation`：准备普通恒星基地升级、模块或建筑操作，并区分空槽建设与已有组件替换。
- `inspect_invasion_state`：读取已知交战国殖民地、逐舰队可达或阻断路径、运输舰队状态和已验证陆军候选。
- `prepare_orbital_bombardment`：原子化准备 `d62d` 姿态设置和以行星对象为目标的 `d32c` 入轨命令。
- `prepare_army_landing`：把目标行星重新解析为当前 colony 对象，再准备 `6f33` 运输舰队登陆命令。
- `prepare_army_recruitment`：选择存档生成的招募候选，把数量 1–5 展开为 N 条普通 `b43d`，逐条等待房主确认。
- `execute_prepared_fleet_order`：通过已启动的会话代理发送上述刚准备的动作，执行前重建同一候选并记录机器事实。
- `inspect_ship_state`：只向模型提供玩家当前可见的舰船设计和相关舰船状态，并报告被排除的隐藏自动生成模板数量；不把完整组件候选库一次性塞入上下文。
- `inspect_ship_design_options`：先列出一份可见设计可用的区段与必需组件，再按选定区段展开合法槽位和组件；猜测隐藏模板 ID 会被拒绝。
- `prepare_ship_design`：以玩家当前可见且可编辑的设计为锚点创建新设计，支持多区段、空槽填充、普通组件、必需组件和自动升级；玩家未指定名称时由舰队 Agent 自主拟定唯一设计名，不覆盖原设计。
- `prepare_fleet_reinforcement`：把一个设计在指定舰队中的目标总数提高到 `target_count`，不是“额外造 target_count 艘”。
- `prepare_new_fleet`：创建一份空 Fleet Manager 模板，不预测返回 ID。
- `execute_prepared_ship_action`：严格串行确认模板增量与单条选中舰队增援请求；不把请求确认写成舰船完工。
- 固定存档续接器：新存档唯一确认模板 ID 后直接写入初始编制并请求增援，不消耗新的模型回合。
- 共享资源预留：经济建设、陆军招募、殖民、恒星基地与舰队支出使用同一份存档哈希账本，拒绝跨 Application 重复花费旧库存。

非房主 `6b33` 请求和房主权威回包已于 2026-09-05 完成零丢包配对验证。移动中的敌军
仍只从玩家自己的 `intel.hostile` 观察出发，按敌方所有者、当前坐标与军力映射到唯一
全局 fleet 对象。对正式战争，解析器还会从顶层战争双方确认交战国，并使用玩家
`terra_incognita.systems` 已知星系列表补齐其恒星基地；没有当前传感器接触时不会向模型
泄露实时军力。候选按超空间航道、外交通行、`restricted_systems` 和敌对
`inhibitor_owners` 逐舰队计算：抑制器所在边境星系本身可攻击，但其后的目标会进入
`blocked_hostile_targets`，直至新存档确认抑制器失效。停战对象即使残留 `hostile=yes`
也不会进入攻击候选。

## 战役路线与阻断清除

`CampaignRoutePlanner` 使用玩家已知星系、超空间航道、战争双方、恒星基地控制权、
`restricted_systems` 和外交关系构造路线。它不会把关闭边境误当成可摧毁目标；当前
没有通行权且不处于战争的领土会形成 `border_access_blockers`。规划器通过有界标签搜索
保留多目标 Pareto 前沿，而不是只返回两个预设答案。目标包括：

- 超空间跳数与需要突破的阻断数量；
- 已知阻断恒星基地军力、行星抑制器数量与守军当前生命池；
- 无法映射来源或军力的未知风险；
- 当前及有限历史部署对整条走廊的累计使用次数，以及单条边的峰值使用次数；
- 每个阻断点列出可确认的恒星基地对象、已知军力、行星抑制器建筑、守军数量与生命池，
  无法映射来源时明确标记未知风险。

安全绕路、最短突破和最少阻断仍作为可解释的基准候选加入同一前沿；其他未被支配的
绕路以 `pareto_alternative` 返回。Pareto 筛选之后，确定性的 UCB 风格探索奖励和拥堵
惩罚才参与推荐排序，因此它可以把下一支舰队引向尚未使用的等价走廊，却不能把关闭
边境或不可行路线变成合法路线。搜索受每星系标签数、总展开数、绕路跳数预算和最多
返回路线数约束，诊断字段会明确报告是否截断。

`inspect_campaign_deployment` 把活动战役、存档中的舰队移动目标和有限的已完成路线记录
合并为部署压力。高军力舰队优先建议为突破力量，中型舰队填补战列线，小舰队优先用于
前线掩护或无人驻守的已占领敌方殖民地；己方紧邻战争目标的边境星系也会列为守备候选。
这些角色属于存档支持的启发式建议，不会扩大玩家授权，也不会代替逐舰队可达性和军力
判断。集中兵力确有必要时，模型仍可选择已占用走廊，但必须依据目标军力说明理由。
`deployment_portfolio` 对舰队做全局互斥分配：较小舰队先补可达的空缺驻防，其余舰队先
按战线构造能够一次闭合已知军力缺口的原子 `task_force_package`，再按当前投入、距离和
探索项选择安全包。若剩余舰队合计仍达不到安全线，该战线只报告缺口，不会留下一个看似
可执行的弱势单舰分配。包内条目带有同一 `task_force_id`、完整成员和是否允许独立出击的
标记；同一舰队不会同时出现在两个推荐任务中。

走廊分散永远排在兵力门槛之后。路线沿途及目标处的每个实际交战星系都会汇总该星系全部已知敌方机动舰队
和恒星基地，而不是只读取被点名的一个对象；当前来源舰队、已在该星系参战的友军以及
存档确认正向该星系机动的友军按舰队 ID 去重求和。默认要求达到敌方已知军力的 1.20
倍，玩家可在控制台把“战役空间军力安全系数”调整为 1.00–5.00。低于门槛时路线仍会
显示，但 `execution_recommended=false`，战役状态为 `reinforcement_required`，固定层拒绝
发出单舰队攻击并给出军力缺口。存在军力未知对象时状态为
`opposition_power_unknown`，不会把未知值当成零。全局部署视图会提供不抽走唯一驻防
舰队的候选增援编组；只有整个编组达到门槛时才会标记 `dispatch_ready`，每支候选仍须
单独通过路径与权限复验。拥堵和探索分数不能创建或拆散一个不满足门槛的进攻编组。

模型负责在路程和战损之间选择，固定层负责执行。`prepare_campaign_route` 之后，每份新
同步存档最多发出一个改变游戏状态的动作：攻击当前可达的第一座恒星基地，或对第一颗
抑制器行星进行轰炸／登陆。动作后必须等待下一份存档确认阻断消失、行星 controller
改变或目标仍然存在。后方 `blocked_hostile_targets` 始终不能被直接构造成攻击命令。

地面决策以运输舰队和守军的当前生命池作保守比较，默认要求进攻方达到守军的 1.25 倍，
玩家可在控制台调整 1.0–5.0。该数字不是完整陆战胜率；科技、将领、士气和伤害类型仍
可能改变结果。`bombard_then_land`、`land_when_advantaged` 与 `bombard_only` 决定何时
登陆，轰炸阈值也由玩家配置。招募后由舰队集合与陆军编制差分唯一识别承载部队的运输
舰队，包括并入既有舰队的情况；自动登陆授权是独立且默认关闭的玩家选项。

## 轨道轰炸、登陆与陆军

入侵能力有独立总开关。军用舰队的 `allow_bombardment` 与运输舰队的
`allow_land_armies` 默认关闭，准备和执行前均重新检查。敌方殖民地必须同时满足：
行星的 owner 或 controller 是当前战争对手、行星保存有效 colony 对象、星系在玩家已知
范围内，而且来源舰队存在当前存档可达路径。

轨道轰炸由同一进程级行动锁保护的两步组成：`d62d` 设置 `selective`、
`indiscriminate` 或 `raiding`，房主确认后再用 `d32c` 的 `132a` 行星目标进入轨道。
登陆使用独立 `6f33`，来源是 `shipclass_transport`，目标字段取 colony ID 而不是行星或
星系 ID。运输舰队必须空闲、未交战、未 MIA 且含有效运输船。

当前自动招募只开放已实抓的 `robotic_army`：固定层验证创始物种的机械特质、
`tech_droid_workers`、本机 `common/armies` 定义、玩家资源、`type=army` 全局队列和己方
招募空间站。Ctrl 招募没有批量字段；数量 N 会被展开为 N 条 `b43d`，任一条未确认便
停止后续步骤。网络确认仅证明命令获房主接受，轰炸、占领和队列结果仍以后续存档为准。

## 跨 Application 资源预留

所有专业 Agent 仍由控制台任务锁串行运行；此外，经济治理和舰队扩张的支出通过
`ResourceReservationLedger` 在战役 SQLite 中原子预留。账本以最新存档 SHA-256 为
作用域：已知成本会从同一份权威库存中累计扣除，费用未知的殖民、升级等动作会独占该
存档的支出资格。确认、暂待存档确认的动作保留预留；发包前失败则释放。新存档一到，
旧哈希下的预留自动标为 superseded，并以新库存重新开始。

## 维修与升级

维修与升级共用一个独立总开关，并分别要求逐舰队 `allow_repair`、`allow_upgrade` 授权。
`8f32` 返港维修记录只携带来源舰队；目的地由游戏依据当前基地状态决定。候选层要求舰队
当前空闲、未交战、未失踪，并且船体、装甲或护盾聚合值能证明存在损伤。

`8f2f` 升级记录同时携带来源舰队和目标 `shipyard_build_queue`。后者由最新存档中己方
带船坞模块的恒星基地提取，不能使用星系 ID、恒星基地索引或 station 对象替代。候选层
还要求至少一艘舰船的 `ship_design_implementation.upgrade` 不是 `0xffffffff`。网络确认
只证明升级命令成立；修复完成度和设计变化仍以新存档为准。

## 民用船、殖民与恒星基地

- 科研船开放探索、勘探、特殊项目、异常现象、考古遗址、星界裂隙与投放重力陷阱中已经验证的选项；工程船开放采矿站、研究站、观测站与特殊项目。若存档显示科研船由内阁科学官带队，星界裂隙会从该舰的合法选项中移除。
- 工程船建站首版限制为当前星系的直接相邻星系。协议确认表示命令成立，不表示基地已经完工；后续存档仍是最终状态依据。
- 自动殖民使用最新存档中的创始物种、玩家殖民船设计和己方恒星基地的 `shipyard_build_queue`。最低宜居度由玩家设置；当前计算是原版物种偏好与无条件环境耐受的保守估计，不猜测事件或临时修正。
- 恒星基地只处理普通原版升级链以及已验证的 `shipyard`、`anchorage`、`crew_quarters`、`hydroponics_bay`。特殊、事件或 Mod 内容应由后续 Content Pack 提供映射。
- `e62c` 现成殖民船路径尚未证明初始规划字段如何持久化，因此只保留在协议兼容性套件，不向 Agent 开放。自动化取消 `6836` 同理不构造。

## 星系内坐标移动

`4f2c` 记录使用有符号 64 位小端整数保存 X/Y，比例为 `100000`。平台从最新存档读取舰队当前 `movement_manager.coordinate.origin`，不允许模型填写或跨星系替换该 origin。模型提交普通十进制坐标，确定性工具负责量化、范围检查和构包。

该能力有独立总开关，且仍受原有舰队移动总开关和逐舰队 `allow_move` 约束。默认坐标绝对值上限为 1000，玩家可在前端修改。成对抓包 fixture 已通过，新的自主发送链仍需下一轮多人实机闭环，因此目前标记为实验功能。

## 定量增援

当前协议证据显示，Fleet Manager 的 `+1` 不是一条绝对数量命令，而是每点击一次发送一条
`5f3b`。因此把目标从 1 提高到 4 必须发送三条独立命令，并分别等待房主确认。选中舰队的
“补充舰队”在干净抓包中只产生一条 `123b`；工具在全部目标增量确认后发送这条请求。
`f23b` 未出现在该动作中，现只作为未解析的全帝国增援证据保留，不会被自动追加。

第一版安全边界：

- 只允许玩家逐舰队启用 `allow_reinforce` 的军用舰队；
- Fleet Manager 模板、设计 ID、当前数量和目标数量都必须来自最新存档；
- 单次目标增量受玩家设置的 1–20 上限约束；
- 存档已有增援队列条目时拒绝重复提交；
- 不允许降低目标、删除舰船、猜测新模板 ID 或宣称舰船已经完工。

## 从零创建舰队

该能力有独立总开关和 1–20 的初始舰数上限，默认关闭。一次完整流程跨越两份存档：

1. 记录玩家当前拥有的模板 ID 集合并发送 `7e3b`；
2. 房主确认后写入战役级待办，但不猜测新 ID；
3. 等新存档中恰好多出一份玩家模板，上传事件立即唤醒固定续接器；
4. 固定续接器按目标数量逐条发送 `5f3b`，再发送单条 `123b`；
5. 再等新存档确认目标编制、队列和可能出现的实体舰队 ID。

若步骤 3 同时出现两份以上新模板，平台无法证明哪一份属于本次动作，因而停止。配置步骤
部分成功时也会等新存档重新计算剩余差额，不会盲目重放。同一份存档对同一工作流最多
尝试一次；续接动作发出后，该存档不再触发一次无意义的模型巡检。新实体舰队不会自动
写入逐舰队权限表，所以移动、攻击和后续增援仍然默认关闭。
