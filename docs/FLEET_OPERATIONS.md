# 舰队行动实验功能

`fleet_operations` 默认关闭。它把存档证据、全局实验开关和逐舰队授权组合成强制执行边界，而不是让模型从名称猜测可用舰队。

## 存档视图

`fleet_profiles.py` 读取玩家国家拥有的 fleet 对象，并报告：

- 对象 ID、可显示名称与舰船数量；
- 军事战斗力；
- 当前星系、移动目标与路径证据；
- 交战、MIA、不可用或证据不确定状态；
- 当前是否属于玩家可直接控制的舰队；
- `d32c` 可使用的已验证目标对象与字段形式。

恒星基地、采矿站等 `station=yes` 对象会保留在底层证据中，但不会显示为可授权舰队。

## 权限

1. 玩家先打开“实验性舰队工具”总开关。
2. 每支新发现舰队的移动与攻击权限默认都是关闭。
3. 玩家在前端逐舰队授权；准备和执行阶段都会重新读取权限与最新存档。
4. MIA、正在交战、已消失、非玩家所有或目标映射不明确的舰队拒绝执行。

模型只能看到当前被平台暴露的工具，不能通过自然语言绕过权限。

## 当前能力

- `inspect_fleet_state`：读取结构化舰队视图。
- `prepare_fleet_move`：验证来源舰队、目标和玩家授权。
- `execute_prepared_fleet_order`：通过已启动的会话代理发送 `d32c`，并记录机器事实。
- `prepare_fleet_attack`：只有玩家打开攻击总开关和逐舰队攻击权限时才可进入预检，但当前仍会明确拒绝执行。

攻击尚未开放的原因不是策略限制，而是协议证据不足：目前缺少同一对局中非房主 `6b33` 请求和房主权威回包的完整配对。v0.5.9 不会用房主样本或字段名称猜测客户端请求。
