# 会话代理模式

`session_proxy` 是 v0.5.9 新增的可选 Windows 实验执行器。原有 `carrier_click` 模式仍是默认值，两者可在网页控制台切换。

## 工作原理

代理必须在合作玩家加入房间前启动。它先透明转发并锁定本局双向可靠 UDP 流，然后观察当前 command epoch 中的非房主 actor 与 serial。每次动作只在纯 ACK 边界插入一条已经验证的完整应用命令，并为连接余下时间维护：

- 客户端到房主的 sender offset 增量；
- 房主到客户端的 ACK 反向映射；
- 同一合作 actor 后续命令的 serial 增量；
- 与本次目标精确匹配的房主权威广播 actor 重标记。

每次插入的长度按实际命令动态计算，不假定固定 153 字节。等长载体改写仍由旧点击链使用。

## 已验证动作

- 建筑建设：`b43d`，支持动态长度 `building_*` 标识符。
- 基础区划建设：`b43d` 内已验证的 district 记录。
- 区域特化：`b43d` 内已验证的 zone 记录。
- 舰队移动：`d32c` 的两个已验证目的地字段形式。

建筑升级、建筑替换仍走 `carrier_click`。舰队攻击 `6b33` 尚未开放构包。

## 操作顺序

1. Windows Agent 以管理员身份启动。
2. 在设置中选择 `session_proxy`，填写房主 IP，并确认实验功能提示。
3. 在合作玩家进入房间之前点击“启动会话代理”，等待 READY。
4. 合作玩家加入房间。若 actor 使用自动识别，本局先自然发出一条合作端命令。
5. 正常运行 Agent。代理可以在同一连接内串行插入多项动作。
6. 先让合作玩家退出多人房间，再点击“停止会话代理”。

代理一旦插入过字节，连接两端的可靠流坐标就不再相同。此时在仍连接房间时终止代理会立即破坏同步，因此控制器默认拒绝这种停止请求。

## 失败关闭

代理只接受已登记动作、合法无符号字段、当前 session ID 和纯 ACK 注入边界。权威回包必须精确匹配动作对象与来源 actor；超时只记录失败，既不猜测成功，也不撤销已经建立的流坐标映射。任何未知记录都会原样转发。
