# v0.5.10

`v0.5.10` 将 IAG 的多领域实验能力整理为可持续运行的自主 Application 架构，并补齐舰船设计、战役路线、地面入侵和跨领域资源协调闭环。Windows 会话代理继续作为推荐执行方式；所有能够改变游戏状态的实验工具仍需玩家显式启用和授权。

## 主要更新

- 新增固定存档身份的 `WorldSnapshot` 与线程安全 `WorldStateIndex`。同一轮自主运行只解压并昂贵解析一次共同世界状态，舰队、入侵、扩张、科研、舰船和路线分析共享该快照及热缓存。
- 新增默认 4 worker 的有界读取池。只有各工具箱明确登记的纯读取和派生计算可以并行；超时任务会被隔离并触发 worker generation 换代，不会永久阻塞后续巡检。
- 三个 Application 可在同一快照上并行检查各自领域；`prepare`、`execute`、网络发包、资源预留和计划修改继续由全局执行锁、SQLite 事务及 revision 校验保护。
- 新增持久化 Application Plan：正常节点由本地条件检查直接续行而不调用模型，局部异常只向快速参谋或领域模型提供受影响节点和相关事实。跨领域联合审查只能投递建议，不能直接改写其他 Application 的计划。
- 网页会话区改为联系人式 Application 通讯界面。经济、舰队和科研拥有彼此隔离的上下文、历史和可见线程；玩家输入、后台报告、未读状态及最近消息预览均按 Application 路由。
- 完成多区段舰船设计闭环：模型可自主命名并选择舰艏、核心、舰艉、武器、防御、辅助、必需组件、战斗电脑、舰船光环及自动升级设置；确定性层验证科技、槽位、功率、名称和完整协议记录。
- 新增有界 Pareto 战役路线搜索、确定性探索奖励、走廊拥堵控制和原子任务编组。攻击前汇总目标及沿途敌军，并以玩家配置的安全倍率阻止弱势舰队被单独派入优势敌军。
- 补齐轨道轰炸姿态、敌方殖民地入轨、运输舰队登陆、定量陆军招募、行星超空间抑制器、舰队维修、船坞升级、选中舰队增援和存档驱动战役续接。
- 模型配置保留 `OpenAI Compatible` 与 `Anthropic API` 两类模板，修复逻辑模型替换、Application 独立模型绑定和端点检测结果展示。
- 会话代理改善 TUN/出口节点流量识别、自动候选归属和人工四元组锁定；人工锁定不绕过 actor、serial、目标或房主权威回包校验。

## 性能与一致性

- 在开发用 75.1 MB gamestate 上，共享冷预热约 8 秒，预热后的四项主要状态读取约 0.18 秒。该数据只衡量本地解析与读取阶段，不包含模型 API 或房主确认时间。
- Windows 环境使用共享内存线程而不是复制完整银河状态的多进程；切换存档时新任务使用新快照，正在运行的一轮不会混用两个存档。
- 路线图、威胁分析和派生索引保留同快照热缓存；单个读取失败不会丢弃已经完成的并行结果。

## 安全边界

- 只有显式白名单中的读取工具进入并行池；任何准备、执行、发包、reservation 和 Plan 写入都保持顺序语义。
- 所有游戏动作在准备和执行前重新确认快照仍为当前上传，并继续要求逐项功能开关、舰队授权、合法候选和确定性协议校验。
- 路线规划不会绕过关闭边境、未知敌军、超空间抑制器或不可达状态；探索分数只在满足硬约束和军力门槛的候选之间排序。
- 模型自然语言不能构成成功证据；房主权威回包或后续同步存档仍是最终事实来源。
