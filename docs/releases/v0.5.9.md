# v0.5.9

`v0.5.9` 是规范化工程结构后的首个正式公开版本。Windows 会话代理已成为推荐执行方式；明确标注为实验性的舰队、科研及扩展协议能力仍需玩家逐项启用。

## 新增

- 将 Windows `session_proxy` 设为推荐和默认执行方式，可在一局连接中串行插入已验证命令。
- 保留 `carrier_click` 兼容模式；只有选择该模式时才显示载体点击校准和固定点击校验。
- 新增动态长度建筑、基础区划和区域特化构包。
- 新增建筑升级与建筑替换的会话代理构包和槽位级回包匹配。
- 新增 `fleet_operations` Application、舰队存档视图、军力与可用性解析。
- 新增舰队总开关、攻击总开关、维修／升级总开关和逐舰队移动、攻击、维修、升级权限。
- 新增已完成真实闭环验证的 `d32c` 舰队移动工具。
- 新增 `4f2c` 星系内坐标状态、确定性构包和逐舰队授权工具，默认关闭并等待实机闭环。
- 新增 `research_strategy` Application，分离三系当前研究、已完成科技和存档合法候选。
- 新增 `062d` 开始研究与 `4533` 停止研究的动态长度构包；中途换题需要独立玩家授权，并严格串行确认。
- 新增玩家舰船设计、Fleet Manager 模板、当前/目标舰数与增援队列解析。
- 新增 `fb2d` 克隆舰船设计工具，以及 `5f3b` 逐艘提高目标编制、单条 `123b` 请求选中舰队增援的实验工具；`f23b` 不再被错误追加。
- 新增 `6b33` 舰队攻击、`8f32` 科研船/工程船自动化、`8f32` 舰队返港维修、`8f2f` 舰队升级和 `e02c` 工程船建造恒星基地的会话代理构包。
- 新增 `3d37` 订购殖民船并殖民，以及 `e62c` 使用现成殖民船殖民的会话代理构包。
- 新增恒星基地 `b43d/cb3d` 升级、`b43d/ca3d` 模块建造/替换和 `b43d/c93d` 建筑建造/替换。
- 新增敌对舰队的玩家情报唯一匹配，以及攻击命令的准备、执行前复验和逐舰队授权。
- 新增玩家舰队船体、装甲和护盾的单舰归一化平均值与中位数；Agent 视图不展开逐舰耐久与 `ship_ids`。
- 新增科研船/工程船已验证自动化选项，包括星界裂隙与投放重力陷阱；由内阁科学官带队时从该舰候选中移除星界裂隙。工程船相邻已勘探星系建站仍受逐船队授权。
- 新增从存档物种、殖民船设计、己方 `shipyard_build_queue` 及匹配版本原版规则生成的殖民候选与最低宜居度设置；多物种差分确认 `3d37.c33d` 是船坞建设队列。
- 新增恒星基地等级、队列、科技、模块和建筑槽候选；替换已有组件需要单独高影响开关。
- 修正超过 255 字节的应用记录扫描与插入；`8f32` 和 `3d37` 使用已验证的 `00 00 PP` 长度前缀。
- 新增独立舰船设计开关、编制增援开关、单次目标增量上限和逐舰队 `allow_reinforce` 授权；全部默认关闭。
- 新增独立的新建舰队开关与初始舰数上限；使用 `7e3b` 创建空模板、新存档唯一解析模板 ID、再配置编制并增援，默认关闭。
- 新增存档事件驱动的固定续接器：新舰队第一阶段由模型决定，后续模板 ID 解析与初始编制不再重复调用模型；同一存档只尝试一次。
- Windows Agent 冻结包包含会话代理 worker、PyDivert DLL 与驱动。

## 兼容性修复

- 模型端点预设收敛为 `OpenAI Compatible` 与 `Anthropic API`；新增 Anthropic Messages、工具结果和流式正文的原生 SDK 链路。已保存的 DeepSeek 端点仍作为 OpenAI Compatible 配置运行。
- 修复 v0.5.8 根级扁平模型配置无法启动 v0.5.9 Windows Agent 的问题。
- `base_url`、`model`、API Key 文件以及旧版请求参数会先在内存中迁移；只有玩家显式保存模型配置时才改写磁盘文件。
- 冻结版 `--health-check` 现在同时验证新版模型池配置与 v0.5.8 扁平配置。
- 修复 `session_proxy` 只按手填房主 IP 监听、导致 Steam 公网/中继会话永远无法锁定可靠流的问题。
- 会话代理发现阶段现会动态读取本机 Stellaris 与 Steam 进程的 UDP 端口归属；锁定后仅接管实际对端四元组。
- 进程端口候选恢复 v0.5.8 的“双向各一包加可靠标记”门槛；未知进程的直连回退继续使用保守的多包门槛。

## 安全边界

- 会话代理是 Windows 默认执行方式，但启动仍需要管理员权限和玩家显式确认。
- 代理必须在合作端进房前启动并保持到离房后。
- 新舰队与民用船的移动、攻击、维修、升级、编制增援、自动化和工程船建站权限默认都不授权。
- 攻击、殖民、民用船和恒星基地工具默认关闭；启用后也只接受最新存档与原版规则生成的候选，并在执行前复验。
- 恒星基地已有模块/建筑替换使用独立的高影响开关，不能由普通恒星基地开关隐式授权。
- 现成殖民船 `e62c` 因初始规划持久化字段未闭合，本版仍不向 Agent 开放。
- 自动化取消命令 `6836` 的选择字段仍未解明，本版不猜测构造。
- `4f2c`、`062d`/`4533`、`fb2d`、舰队维修／升级与 Fleet Manager 编制增援已有成对样本和离线 fixture，但仍保持实验状态。
- 增援请求的房主确认不等于舰船完工；实际队列和数量必须由新存档确认。
- 模型自然语言不能把动作标记为成功；权威回包或后续存档才是机器事实。

## 测试重点

- 公网、局域网和 Steam Relay 条件下的整局代理稳定性。
- 同一连接中的多次建设与舰队移动。
- 24 位可靠流 offset 回绕后的 sender epoch 处理。
- 合作玩家重同步、掉线和重新进房时必须重新启动代理。
- 舰队毁灭、MIA、交战与所有权变化后的权限失效。
