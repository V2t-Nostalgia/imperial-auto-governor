# 舰队行动 Application

该 Application 读取最新同步存档中的玩家舰队、军力、移动、交战、MIA、舰船设计、
Fleet Manager 模板与增援队列，并把玩家逐舰队授权作为本地强制边界。船体、装甲和
护盾按单舰最大值归一化，只向模型提供舰队平均值和中位数，不展开单舰列表。新发现的
舰队默认禁止模型调用。

`d32c` 跨星系移动命令已经完成真实会话闭环，但仍依赖 Windows 会话代理，必须在加入
房间前启动并保持到退出房间。`4f2c` 星系内坐标移动已有成对样本、存档坐标解析和离线
构包测试，默认关闭并等待新执行链实机闭环。它复用逐舰队移动权限，并由玩家配置坐标
绝对值边界。

`6b33` 攻击记录已取得非房主请求与房主权威回包的零丢包配对，其构造器和精确回包
匹配已经接入会话代理。舰队 Application 从最新存档中只读取玩家已经获得情报的敌对
舰队，以所有者和坐标做唯一匹配，并在准备与执行两个阶段重新核对攻击总开关、逐舰队
授权和目标可用性；模型不能提交候选列表之外的敌对对象 ID。

科研船与工程船的 `8f32` 自动化、工程船的 `e02c` 恒星基地建设也已经接入独立候选与
逐舰队授权。科研船已验证选项包括星界裂隙与投放重力陷阱；存档若显示该舰由内阁科学官
带队，候选层会移除星界裂隙。工程船首版只能在相邻、完整勘探、无主、无现存恒星基地
且没有可见敌军的星系建站。尚未闭合选择字段的 `6836` 自动化取消不会由 Agent 猜测构造。

军用舰队的 `8f32` 返港维修和 `8f2f` 指定船坞升级使用独立总开关以及逐舰队维修／升级
授权。维修候选必须有存档可见损伤；升级候选必须有升级设计，并从己方恒星基地读取精确
的 `shipyard_build_queue`。模型不能用星系或恒星基地对象猜测该队列。

扩张状态由 `state/expansion_profiles.py` 提供。`3d37` 自动殖民只使用存档中的创始物种、
殖民船设计、可用船坞来源和匹配游戏版本的原版宜居度规则，并受玩家最低宜居度限制；
首版只开放已经成对验证的城市星球与矿产星球规划。现成殖民船 `e62c` 因规划持久化字段
尚未闭合，仍只保留在离线协议验收中，不向模型开放。

恒星基地升级、模块和建筑操作同样只接受最新存档与原版规则生成的候选。普通建设与
替换已有组件分属两个开关；高影响替换不会被普通恒星基地授权隐式放行。

完整舰船设计与定量增援是两个独立且默认关闭的实验功能。设计工具仍以存档中属于玩家
的现有设计为锚点，但已支持标准军舰的多个区段、空槽填充、区段内全部组件、各舰型
必需组件（包括泰坦／主宰的舰船光环）和自动升级开关。模型必须先按需查询区段与槽位候选；平台用匹配版本的本机规则、
玩家已研究科技、槽型、作战电脑角色和可解析的功率余额复验，不允许提交任意裸 ID，
也不会覆盖原设计。定量增援使用 Fleet Manager 语义：
玩家或模型给出某支舰队、设计 ID 和目标总数；平台按差额逐条发送 `5f3b` 增加编制，
随后发送单条 `123b` 选中舰队增援请求。每一步都等待房主确认。`f23b` 没有出现在该
动作的干净抓包中，因此不会被自动追加。

房主确认只证明模板修改和增援请求成立，不证明舰船已经建成。工具结果固定报告
`ships_completed = 0`，并要求后续新存档确认增援队列和实际舰数。第一版不允许降低
目标编制。

从零创建舰队使用单独开关和持久状态机。平台发送已成对验证的 `7e3b` 创建空模板，但
不会根据连续数字猜 ID；它等待新存档从玩家模板集合中唯一解析新增对象，再按目标数量
由固定续接器执行 `5f3b` 与单条选中舰队增援，不再次唤醒模型。发生歧义时续接器
停止且不猜字段；新实体舰队仍默认没有任何逐舰队授权。

`conversation_agent.py` 提供独立舰队模型回路，`prompts/fleet_operator_zh.md` 严格限制
其角色职责。该 Agent 使用独立模型绑定和历史，只能看到本目录工具；没有玩家明确任务
时，后台巡检不得凭空创造调动目标。网页“对话对象”可直接选择舰队行动 Agent。
